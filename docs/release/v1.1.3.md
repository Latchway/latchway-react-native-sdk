# Latchway React Native SDK 1.1.3

This patch expands the minimum host to React Native 0.74.0 with React 18.2.0.
New Architecture remains required. The peer ranges are:

```json
{
  "react": "^18.2.0 || ^19.0.0",
  "react-native": ">=0.74.0 <1.0.0"
}
```

Use the React version required by your chosen React Native release. The broader
range admits newer 0.x releases; it does not claim every release has been tested.
The main development and full Firebase/LangChain example baseline remains 0.82.

## Install or upgrade

```sh
npm install --save-exact @latchway/react-native@1.1.3
```

Older hosts need native build settings as well as the npm upgrade. Follow the
[versioned compatibility guide](https://github.com/Latchway/latchway-react-native-sdk/blob/v1.1.3/docs/react-native-compatibility.md),
including the optional RN 0.74 Android adapter and its exact build-only Gradle
plugin setup. Android resolves the React Native runtime and Codegen from the
consuming app instead of assuming a library-local 0.82 installation.

No runtime dependency was added. Native iOS/Android SDK pins remain 1.0.0,
and the JavaScript API, wire protocol and native security boundary are unchanged.
The adapter translates generated autolinking names; it does not patch installed
React Native source or replace native providers.

## Validation

The minimum host passed strict archive installation, public TypeScript API
checking, all 19 Codegen methods, both Metro bundles, a complete arm64 Android
Debug APK build and an unsigned arm64 iOS device-target build. The 0.82 baseline
retains Android library compilation and both example bundle checks. SDK unit
tests, runtime tests, lint, types and compatibility checks also pass.

These are build and package checks, not fresh physical-device attestation or
gateway end-to-end evidence. Historical release-policy tests still reference
previously removed workflows; the full legacy `pnpm check` is not claimed green.
The existing simple trusted-publishing workflow is retained.
