# Latchway React Native SDK 2.0.0

This major release makes supplied-identity shared native accounts the only root
integration. Native or React Native can configure first; identical configuration
joins the existing app and account without Firebase or a mandatory host bootstrap.

## Upgrade

- Install `@latchway/react-native@2.0.0`, update CocoaPods, and rebuild both native
  apps. Native pins are iOS 2.0.0 and Android 1.2.1. JavaScript client 1.1.0 and
  gateway client contract 1.1.0 / wire 3 are unchanged.
- Replace `createLatchwayClient` and old authority/activation callbacks with
  `Latchway.configure`, `app.signIn` or `app.restore`, and account-bound clients.
  Application code supplies identity metadata and ID tokens; Latchway imports
  no Firebase dependency and owns no external authentication provider.
- The private TurboModule bridge uses ABI 3 and 17 tokenless transport methods.
  Do not ship this JavaScript update over an ABI-2 native app.
- Storage starts fresh. No historical keys/sessions are scanned or adopted.
  Current account cleanup, root/extension isolation and retirement fences remain.
- Use `await app.signOut()` for application logout and retry actual secure-storage
  failures before accepting another account. Sign out the external auth provider
  separately. Screen disposal does not sign out siblings or reset quotas.

The native Fetch body parsing fix from 1.2.1 and app sign-out from 1.3.0 remain
included, with regression coverage retained against the new API.

## Development attestation

Server 1.1.3 adds `appAttest.environment: any` to accept either verified Apple
environment. Distribution categories remain separate. TestFlight uses production
Apple evidence; local development normally uses development evidence. Never put
`any` in the Apple entitlement or SDK configuration.

Google Play testing responses require explicit server-side Development policy,
retain `debug` trust and still undergo configured identity/verdict/binding checks.
There is no client bypass flag. Native SDKs handle attestation and bounded
App Attest invalid-key recovery. See [the guide](../development-attestation.md).

React Native >=0.74 <1 and React 18.2 / 19 peers remain unchanged. Broader admitted
minor versions are not a claim of exhaustive testing. No new physical-device,
TestFlight, Google testing-token or production-distribution proof is claimed.
