# Latchway React Native SDK 1.2.0

Shared native accounts with developer-supplied identity. Either RN or native
can configure first and reuse the same session without a native-team bootstrap
or a Firebase-dependent companion.

The new API exposes `signIn`, `restore`, `currentAccount`, account-scoped
`updateIdToken`/`logout`, and `makeClient`. Pure `firebaseProject`/`jwtIdentity`
helpers and an optional injected auth binding carry no Firebase dependency.
Token updates are gateway-verified, expired identity is suspended, and native
generation fencing prevents late account-A work from affecting account B.

Required release pairing: server 1.1.1+, JavaScript client 1.1.0, iOS 1.2.0 and
Android 1.1.0. The RN package pins those native dependencies. The server must
explicitly enable shared native callers for the existing required attestation
policy. Legacy constructor behavior is retained on wire 2; shared apps use wire 3.

React Native `>=0.74.0 <1.0.0` and React `^18.2.0 || ^19.0.0` remain. Android
library compile SDK and minimum compile SDK are 34; host requirements are separate.

Follow [the integration guide](../supplied-identity.md). External auth changes
and token renewal remain application-owned. Physical Android/extension
acceptance is separate from local fixture and consumer-build verification.
